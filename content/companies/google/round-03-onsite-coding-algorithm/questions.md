# Google — Round 3: Onsite — Coding / Algorithm Rounds

**What this round assesses:** Data structures, algorithm complexity, clean code, edge cases, communication, and optimization thinking.

## Format

2–3 video rounds, 45 min each, typically in a shared Google Doc with follow-ups such as optimization or large-input variants.

## Online assessment details

Platform: Google Docs live coding rather than a separate OA platform. Number/type: 1–2 coding problems per round. Topics: binary search, heaps, graphs, DP, sliding windows, Union-Find, caches. `official`

## Representative questions

1. Median of Two Sorted Arrays — classic hard binary search problem. `anecdotal`
2. Merge K Sorted Lists — heap/priority queue and linked list manipulation. `anecdotal`
3. Word Ladder — BFS on an implicit graph. `anecdotal`
4. Trapping Rain Water — two-pointer and stack approaches. `anecdotal`
5. Regular Expression Matching / Wildcard Matching — DP with careful state definition. `anecdotal`
6. Serialize and Deserialize Binary Tree, with follow-up on trees too large for memory. `anecdotal`
7. Minimum Window Substring — sliding window with hash map. `anecdotal`
8. Alien Dictionary — topological sort on inferred character graph. `anecdotal`
9. Number of Islands II — dynamic Union-Find. `anecdotal`
10. Design an LRU Cache using `unordered_map` plus a custom/list node structure in C++. `anecdotal`
11. How does `std::priority_queue` work internally? `inferred`
12. What is the time complexity of `std::map::insert`? `inferred`
13. Why did you use `reserve()` on your vector? `inferred`
